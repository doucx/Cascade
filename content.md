## [WIP] refactor(compiler): 为 WiringHarness 实现锁定机制以强制职责分离

### 用户需求

根据架构路线图 4.1，需要为 `WiringHarness` 实现一种读写分离机制。在编译的第二阶段（Wiring），`WiringPolicy` 应该被禁止调用任何创建节点的方法（如 `add_node`），如果尝试调用，则必须抛出一个明确的 `ArchitectureViolationError`。

### 评论

这是对我们新架构的“宪法级”加固。我们不仅通过代码结构分离了职责，现在还要通过运行时检查来强制执行这一分离。这是一种防御性编程，旨在保护系统的长期健康。它确保任何未来的开发者（包括我自己）都无法轻易地、意外地绕过我们精心设计的两阶段编译模型，从而从根本上杜绝此类架构问题的再次发生。

### 目标

1.  在 `wiring/harness.py` 中定义一个新的异常类型 `ArchitectureViolationError`。
2.  为 `WiringHarness` 类添加一个内部的“锁定”状态（例如 `_locked` 标志）。
3.  添加一个 `lock()` 方法来激活这个锁定状态。
4.  修改 `add_node` 和 `add_subgraph` 方法，在执行前检查锁定状态，如果已锁定则抛出 `ArchitectureViolationError`。
5.  在 `builder.py` 的 `build` 方法中，在第一阶段（Materialization）和第二阶段（Wiring）之间调用 `wire.lock()`。

### 基本原理

我们将为 `WiringHarness` 引入一个简单的状态机（`unlocked` -> `locked`）。
-   在**第一阶段（Materialization）**，`WiringHarness` 处于 `unlocked` 状态，允许 `ExpansionPolicy` 通过它自由地创建节点。
-   在两个阶段之间，`Builder` 将调用 `wire.lock()`，将其切换到 `locked` 状态。
-   在**第二阶段（Wiring）**，`WiringHarness` 处于 `locked` 状态。此时，任何对 `add_node` 或 `add_subgraph` 的调用都将被视为非法的架构越界行为，并立即被一个运行时异常所阻止。

这种机制以最小的侵入性，为我们的架构提供了强大的运行时保障。

class WiringError(ValueError):
    pass


class ArchitectureViolationError(RuntimeError):
    pass


class WiringHarness:
    def __init__(self, graph: BipartiteGraph):
        self.graph = graph
        self._locked = False

    def lock(self) -> None:
        """Locks the harness, preventing any further node additions."""
        self._locked = True

    def add_node(self, node: PhysicsNode) -> None:
        if self._locked:
            raise ArchitectureViolationError(
                "Cannot add nodes during the Wiring phase. "
                "Node creation is restricted to the Expansion phase."
            )
        if node.id in self.graph.nodes:
            raise WiringError(f"Node ID collision: '{node.id}' is already registered.")
        self.graph.nodes[node.id] = node

    def add_subgraph(self, subgraph: SubGraph) -> None:
        if self._locked:
            raise ArchitectureViolationError(
                "Cannot add subgraphs during the Wiring phase. "
                "Node creation is restricted to the Expansion phase."
            )
        for node in subgraph.nodes.values():
            # We use setdefault logic or simple overwrite?
            # SubGraphs should have unique IDs generated by generator.
            if node.id in self.graph.nodes:
                raise WiringError(
                    f"Subgraph Node ID collision: '{node.id}' is already registered."
                )
            self.graph.nodes[node.id] = node
